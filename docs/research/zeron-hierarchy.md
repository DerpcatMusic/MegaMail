# Zeron visual hierarchy anatomy

Zeron source is pinned to 037f4c10d67a38175b2386e776aba54355b4e941. This note reads the rendered screens alongside the GPUI row and shell code. The canonical palette, font, geometry, platform materials, and component source map live in [zeron.md](zeron.md); this note focuses on why the hierarchy reads clearly and how that hierarchy should translate to mail.

## The hierarchy, from outside inward

1. **A quiet frame gives the work area the most visual weight.** In the sidebar fixtures, the shell is a narrow left strip and the transcript/work pane takes almost all remaining width. The pane is largely unboxed and near-black in dark mode; one-pixel boundaries and tonal separation define the sidebar. The top identity row orients the user, while the large open center is allowed to stay quiet. This is not empty-card UI: the shell uses #060606 for the main plane and #0d0d0d for the sidebar, then reserves raised fills for actual controls ([theme.rs:1140-1167](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/crates/ui/src/theme.rs#L1140-L1167), [shell.rs:13195-13285](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/crates/ui/src/shell.rs#L13195-L13285)).

2. **The sidebar is a navigation index, not a stack of cards.** Group labels such as Pinned, Focus, Later, Sessions, and Archived sit above rows in smaller, muted type. The sections are separated by a little vertical air instead of horizontal rules. Compact mode is 29px high with a 2px list gap; detailed rows add a context line and optional source metadata. The source computes the row height from the visible metadata, so disclosure changes the reading rhythm without leaving phantom gaps ([shell.rs:948-984](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/crates/ui/src/shell.rs#L948-L984), [shell.rs:8410-8429](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/crates/ui/src/shell.rs#L8410-L8429), [sidebar-layout README:11-20](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/docs/screenshots/sidebar-layout/README.md#L11-L20)).

3. **Each row has one clear primary label and a quieter frame of context.** In detailed mode, line one carries project/device context with status or relative time at the right; line two places the harness/project identity beside the session title; branch and pull-request metadata sit below. The title is 13px/17px, context is 11px/14px, and status labels are 10px medium. Compact mode omits the context line and keeps status/icon/title left with badge/time right. This is deliberate progressive disclosure, not just smaller text ([shell.rs:7289-7292](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/crates/ui/src/shell.rs#L7289-L7292), [shell.rs:7780-7848](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/crates/ui/src/shell.rs#L7780-L7848), [typography.rs:80-123](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/crates/ui/src/typography.rs#L80-L123)).

4. **The selected row is identified by a single surface change.** The selected background is a soft rounded wash; there is no row outline. Unselected text rests at reduced opacity, while the selected title returns to primary text. Hover brightens the wash and text over the same 150ms transition. Selection does not drift when the pointer enters it, and hover reveals Archive in the existing trailing slot instead of making every row reserve another button-width of blank space ([shell.rs:7613-7676](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/crates/ui/src/shell.rs#L7613-L7676), [shell.rs:7319-7325](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/crates/ui/src/shell.rs#L7319-L7325), [sidebar fixture notes:20-33](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/docs/screenshots/sidebar-layout/README.md#L20-L33)).

5. **The bottom composer is the persistent action anchor.** In the work pane, transcript content scrolls behind the lower chrome while a flex spacer keeps the composer/status stack at the bottom. The composer itself is capped at 768px for a new thread, centered, and rendered as one rounded surface with a restrained border and optional in-app frost. The rest of the canvas stays open. The components inside that surface use a simple left-to-right order: attachment/input, model or mode, then primary send action ([shell.rs:296-305](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/crates/ui/src/shell.rs#L296-L305), [shell.rs:10591-10653](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/crates/ui/src/shell.rs#L10591-L10653), [composer.rs:11179-11203](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/crates/ui/src/composer.rs#L11179-L11203)).

6. **Spacing does much of the grouping work.** Zeron's base ladder is 4/8/12/16px; the sidebar adds a 2px row rhythm and 6px vertical row padding. A small radius on the row is enough to make selection legible against a flat list. With that spacing and a modest type ladder, there is little need for repeated borders, badges, or deeply elevated panels. The surface and interaction tokens that support this are summarized in [zeron.md](zeron.md#hierarchy-and-state-grammar) and visualized in the [atlas](design-atlas.html).

## Why the sparse and translucent look holds together

The calm look is structural before it is material. One region owns the main task, one selected item marks context, and the composer is the principal persistent action. Zeron does not place a card behind every list row or text block. Information hierarchy mostly comes from alignment, type size/weight, and tonal role; borders are reserved for actual edges and the composer boundary.

Translucency adds depth only where the layout already has a clear plane. The sidebar is a coherent shell, while the composer and floating menus are distinct surfaces. The composer uses one backdrop treatment around the complete pill; its border and fill protect text over the scrolling transcript underneath. On Linux, the window uses an opaque theme tint because compositor blur cannot be assumed; supported in-app floating surfaces can still use the separate GPUI blur path. That separation is why the look can survive without wallpaper or desktop blur ([theme.rs:787-812](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/crates/ui/src/theme.rs#L787-L812), [theme.rs:914-928](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/crates/ui/src/theme.rs#L914-L928), [theme.rs:1113-1137](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/crates/ui/src/theme.rs#L1113-L1137)).

Dark and light mode keep the same roles but change the contrast strategy. Dark uses the near-black content plane and only slightly lighter shell, with a translucent pale hover/selection wash. Light mode uses a white canvas inside a light gray shell; its hover/selected wash is a much softer dark tone. A fixed percentage or simple color inversion would make the selected row too strong in one appearance and too weak in the other. Both the source tokens and screenshots show that the roles are remapped, not mechanically inverted ([theme.rs:1140-1188](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/crates/ui/src/theme.rs#L1140-L1188), [theme.rs:1239-1288](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/crates/ui/src/theme.rs#L1239-L1288), [theme.rs:1773-1786](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/crates/ui/src/theme.rs#L1773-L1786)).

## Mail-specific translation

The following is design inference for MegaMail, not behavior observed in Zeron:

| Zeron element | Preserve the hierarchy | Email-specific content |
| --- | --- | --- |
| Persistent sidebar groups | Keep account/folder navigation in one steady, scan-friendly rail; use section labels and spacing before adding divider lines. | Mailboxes, labels, and account identity. |
| Compact session row | Keep one primary line, quiet supporting metadata, and right-aligned time or state. Preserve the option to show a richer row when the user asks for more context. | Sender and subject are the primary scan targets; snippet, date, and labels are supporting metadata. Unread needs a distinct typographic state, not a copied Zeron activity color. |
| Selected/hover row | Keep selection as one soft fill and hover as a nearby but distinct wash; reveal row actions in the trailing slot. | Selected message/thread; hover can expose Archive or Star without permanently consuming list width. |
| Conversation canvas | Keep a broad, continuous reading surface with restrained top-level metadata and no default card around every text block. | Thread subject and participants lead into readable, well-spaced message bodies; quoted history and attachments remain subordinate until opened. |
| Persistent composer | Keep the recognizable low anchor and the clear grouping of input and primary action. | A contextual reply editor belongs to an open thread. A new-message flow still needs recipient and subject fields; Zeron's prompt pill cannot simply be copied as a full email compose form. |
| Status / activity colors | Preserve semantic color only where it communicates a real process state. | Do not reuse Zeron's Working, Done, Queued, or Failed colors to mean unread. Use text weight plus an unobtrusive marker for unread, while keeping failure and sync states semantically separate. |

The practical reading order for a mail screen is therefore **folder/account → sender + subject → snippet/date → selected thread → message body → reply action**. This is an adaptation of Zeron's spatial grammar, not a claim that Zeron already contains an email list or reader.

## Linux-first reading and proof limits

Zeron's screenshots prove the X11 fixture geometry and its dark/light component states. The sidebar fixture description explicitly says native X11 checks were done; native macOS and Windows interactions were not checked there. The README hero is macOS glass with wallpaper and should not become a Linux acceptance image. The code says Linux's main window tint is fully opaque while floating GPUI surfaces can use scene-level frost. For MegaMail, judge the hierarchy first on solid dark/light surfaces with no wallpaper; only then keep any in-app blur that the chosen GPUI Kit renderer supports and that preserves contrast. The Linux backend may use a transparent window background for CSD corner cutouts while painting an opaque app surface, so “transparent window background” does not mean a translucent main canvas ([theme.rs:787-812](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/crates/ui/src/theme.rs#L787-L812), [theme.rs:1113-1137](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/crates/ui/src/theme.rs#L1113-L1137), [fixture notes:20-33](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/docs/screenshots/sidebar-layout/README.md#L20-L33)).

There is no unread-mail state in the reviewed Zeron sidebar, and the reference screenshots do not show a disabled folder or message action. Zeron does have task/session status states, and a disabled titlebar history control dims its icon to 35% opacity; that is only a visual reference for disabled controls, not an email unread rule ([shell.rs:7319-7325](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/crates/ui/src/shell.rs#L7319-L7325), [shell.rs:12503-12531](https://github.com/zeronsh/zeron/blob/037f4c10d67a38175b2386e776aba54355b4e941/crates/ui/src/shell.rs#L12503-L12531)).
